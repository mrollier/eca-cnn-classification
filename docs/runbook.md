# Runbook: the training runs

Everything that needs no training is regenerated by `python reproduce.py all`
in a few minutes. This document covers the rest: 34 training runs behind the
default-CNN, trimmed-CNN, augmentation-table and final-model numbers, and how
to check the chapter against the original Colab data and models.

## 1. Environment

Any machine with Python 3.9–3.11 works. A GPU helps but is not needed; the
networks are small.

```bash
git clone https://github.com/mrollier/eca-cnn-classification.git
cd eca-cnn-classification
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e . --no-deps
python reproduce.py quick                         # data + checks, ~3 min
```

On a Linux workstation with an NVIDIA GPU, the official TensorFlow 2.15
image has the right versions:

```bash
docker run --gpus all -it --rm -v "$PWD":/work -w /work tensorflow/tensorflow:2.15.0-gpu bash
pip install -r requirements.txt && pip install -e . --no-deps
```

`train.deterministic_ops: true` (the default) makes re-runs on the same
hardware identical. If an op on the GPU refuses to run deterministically,
add `--set train.deterministic_ops=false`.

## 2. The runs

`python reproduce.py train` runs them all in this order, skipping runs that
have finished. `--only <name> ...` selects some. A run can also be started
directly, e.g. `python scripts/train.py --config configs/default_rules.yaml`.

| Name | Config | Runs | Per epoch (laptop CPU) | Epochs | Feeds |
|---|---|---|---|---|---|
| `default_rules` | `default_rules.yaml` | 1 | ~100 s | ≤ 50, early stop | Sec. 2.3; Fig. default_model-misidentified_val_set |
| `default_classes` | `default_classes.yaml` | 1 | ~95 s | ≤ 50, early stop (chapter: 12) | Sec. 2.3; Fig. default_model-all_wrong_LP_classes |
| `trimmed_classes`, `trimmed_rules` | `trimmed_*.yaml` | 2 | ~40 s | ≤ 100, patience 10 | Sec. 3.2 |
| `mlp_*` | `mlp_*.yaml` | 2 | ~35–42 s | ≤ 50, early stop | Sec. 3.2 (fully-connected comparison) |
| `augmentation_table` | `augmentation_table.yaml` | 18 | ~40–50 s | ≤ 100, patience 5 | Tab. assessment_data-augmentation |
| `augmentation_table__faithful` | same, `mode=faithful`, cells 9–11 and 15–17 | 6 | ~45 s | ≤ 100 | the coarse-grained and "all" rows as published |
| `final_classes`, `final_independent` | `final_*.yaml` | 2 | ~60 s | 100, no early stop | Sec. 3.4; Fig. confusion_matrix-final |
| `final_*__faithful` | same, `mode=faithful` | 2 | ~60 s | 100 | the published final model (98.17% / 61.25%) |

Per-epoch times are the estimates of the `--smoke` runs on an Intel
i7-9850H laptop without GPU (validation adds a few seconds per epoch). The
whole list comes to roughly a day on that machine: about 7 h for the four
final models, 10–15 h for the 24 augmentation runs (depending on early
stopping), and 2–3 h for the rest. The chapter reports 25 s per epoch for the
default CNN on an NVIDIA T4.

Only the cells that use coarse-graining are re-run in faithful mode. For the
other runs the two modes are identical.

## 3. After training

```bash
python scripts/collect_results.py                    # data/results/training_results.md and .json
python scripts/collect_results.py --set mode=faithful
python scripts/make_figures.py
python scripts/make_figures.py --set mode=faithful
```

`collect_results.py` puts each value next to the chapter's. Commit
`data/results/training_results*.{md,json}` and update the results section of
the README with those numbers only.

Each run folder `output/runs/<name>/` holds `config.yaml`, `model.keras`,
`history.csv`, `metrics.json` and `predictions_<set>.npz`. When training
happens on another machine, copy these folders back into `output/runs/`;
the figures and tables need only `metrics.json` and the predictions.

## 4. Checking the chapter against the original Colab files

The original datasets and models are on Google Drive under
`Colab Notebooks/Cellular Automata/Spacetime Diagram Classification/`
(`Files/` and `Models/`). They were generated without a seed, so they are the
only exact copy of the chapter's data. Every script accepts them:

```bash
D="<path to>/Spacetime Diagram Classification"   # contains spaces: keep the quotes
export ECA_CNN_ORIGINAL_DATA="$D/Files"           # read by configs/base.yaml (paths.original_data_dir)

python scripts/run_benchmark.py --set data.source=original   # faithful mode should give 370 / 33 (§3.2)
python scripts/run_exact_cnn.py --set data.source=original   # settles 331 vs 384 (docs/provenance.md §7.6)

# The published final models on the original test set (expected: 98.17% and 61.25%, docs/provenance.md §2)
python scripts/evaluate_model.py --config configs/final_classes.yaml --sets test --set data.source=original \
  --model "$D/Models/reproducing_silverman2019_trimmed_classes_final_2x2-4-4-MP-4-4-16_bool-invert_mirror_coarse-grain"
python scripts/evaluate_model.py --config configs/final_independent.yaml --sets test --set data.source=original \
  --model "$D/Models/reproducing_silverman2019_trimmed_independent_final_2x2-4-4-MP-4-4-16_bool-invert_mirror_coarse-grain"

# The default CNN (expected: 0.998530 / 0.998520 for rules, as printed in the notebook)
python scripts/evaluate_model.py --config configs/default_rules.yaml --sets train val --set data.source=original \
  --model "$D/Models/reproducing_silverman2019_default64x64_rules"
python scripts/evaluate_model.py --config configs/default_classes.yaml --sets val --set data.source=original \
  --model "$D/Models/reproducing_silverman2019_default64x64"
```

On Windows PowerShell, set the variable with
`$env:ECA_CNN_ORIGINAL_DATA = "$D\Files"`.

The train/validation split repeats the notebooks' procedure, including its
dependence on the `(n, 1)` shape of the label arrays (docs/provenance.md
§7.1). If the default CNN's training and validation accuracies come out as
printed in the notebook, the split was reproduced. If the validation
accuracy is noticeably higher than the notebook's, the "validation" set
overlaps the notebook's training set.

Benchmark and exact-CNN results on the originals are written to
`data/results/*_original.json`, next to the regenerated ones.

The original data occupy 1.2 GB on disk. They are read with memory mapping
and packed into about 150 MB of memory.

Model folder names used by the notebooks:

- `reproducing_silverman2019_default64x64_rules`, `reproducing_silverman2019_default64x64`
- `reproducing_silverman2019_trimmed_2x2-4-4-MP-4-4-16` (classes). The rules
  variant cannot have been saved by the notebook as it stands (§4).
- `reproducing_silverman2019_trimmed_{classes,independent,rules}_2x2-4-4-MP-4-4-16`
  followed by `_bool-invert`, `_mirror`, `_coarse-grain`, `_salt-and-pepper0p01`
  as applicable (the augmentation table)
- `reproducing_silverman2019_trimmed_{classes,independent}_final_2x2-4-4-MP-4-4-16_bool-invert_mirror_coarse-grain`
